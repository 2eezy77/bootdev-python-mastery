# Unit-test
* Testing your code with a separate file.
* targets specific code in file for expected outcome.
* In Boot.dev, the unit_test.py file tests' functions in your main.py file not just certin prnt() 

# Debugging (test v. push)
* working on your own code before pushing by establishing unit tests that tests parts of code
* using print() is the best to test as you go

# Process for solving coding problems
* understand the lesson & assignment b4 writing code.
* write code step by step, using print() to debug small sections; don't end up trying to solve large blocks
* redo assignment if you find yourself stuck or peaking at solution.

# Traceback Error
* Most common error where the interpreter points out the error, walking us through how it ran our code, then it prints a type error after pointing the area of question.
* Running into traceback errors just means room for improvement, allowing the programmer to understand their code better and not run into the same mistake.
